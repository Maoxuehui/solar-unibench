该文本主要系统性地定义了太阳能预测中存在的各类数据缺陷，并提出了一套模块化的数据修复“原语”工具箱，最后阐述了如何将这些原语封装进一个**基于智能体的自动化决策工作流**中。
具体内容总结如下：
### 1. 基准数据集选取
选取了4个具有代表性的公开数据集，以覆盖不同的数据体制：
*   **SKIPP**：单站点、高频光伏+天空图像（测试图像质量控制）。
*   **GEFCom2014**：纯结构化数据，但**缺失地理元数据**（测试元数据推断能力）。
*   **Comprehensive Solar**：密集的多模态数据（地面+图像+卫星+NWP），存在**严重的跨模态异步**（测试时间对齐能力）。
*   **SITS**：长期的、多站点的卫星上下文数据（测试跨站点迁移和空间信息利用）。
### 2. 数据缺陷的形式化定义（分类学）
文本将缺陷分为三大类，并给出了严格的数学定义：
*   **结构化数据缺陷**：
    *   **缺失值**：NaN的传播问题。
    *   **不规则采样**：实际采样间隔偏离固定间隔 $\Delta t_{\rm fixed}$ 的方差。
    *   **重复/非单调时间戳**：时间序列不严格递增。
    *   **异常值与物理不一致**：数据超出物理边界（如负值或超装机容量）。
    *   **时区不一致**：夏令时或转换错误导致的时间偏移。
    *   **地理元数据缺失**：无经纬度导致无法计算太阳几何和晴空辐照度。
*   **非结构化（图像）数据缺陷**：
    *   **缺失/损坏帧**：文件无法读取。
    *   **图像质量退化**：通过质量评分 $Q(X_t)$ 衡量的模糊、过曝、低对比度等问题。
    *   **无效区域/遮挡**：如鱼眼镜头的黑边、建筑物遮挡（通过无效像素比 $\rho_{\rm invalid}$ 衡量）。
    *   **局部像素异常**：坏点、眩光等局部离群点。
    *   **几何错位**：相机移位导致像素与天空方向的映射发生漂移。
*   **跨模态缺陷**：
    *   **跨模态异步**：图像时间戳与结构化数据时间戳的差值超过容差 $\epsilon_t$，导致“图文不符”的标签噪声。
### 3. 数据修复策略与映射矩阵
由于数据问题通常是耦合的，文本没有采用“一对一”的修复方式，而是提出了一个**可组合的修复原语工具箱**，并提供了两张矩阵表说明哪个原语适用于哪个问题。
**核心修复原语包括：**
*   **结构化修复**：
    1.  **删除与重对齐**：剔除无效行，强制时间轴单调递增。
    2.  **插值**：基于物理上下文（如晴空背景）填补缺失值。
    3.  **异常过滤与物理修正**：将目标值强制截断在物理可行区间 $[y_{\min}, y_{\max}]$ 内。
    4.  **时间对齐与标准化**：统一转UTC，或通过相关性推断时区偏移。
    5.  **地理元数据推断**：通过最小化观测曲线与候选网格上晴空曲线的残差，反推经纬度。
    6.  **数据质量分析**：生成缺陷热力图等诊断报告供人工审查。
    7.  **预测窗口质控**：确保整个滑窗内的数据均有效，否则丢弃整个样本。
*   **非结构化与跨模态修复**：
    1.  **帧级筛选与归一化**：根据 $Q(X_t)$ 剔除差图，应用 CLAHE 等算法增强对比度。
    2.  **时间对齐**：在容差 $\epsilon_t$ 范围内，为结构化数据匹配最近的有效图像。
    3.  **视觉特征提取**：提取红蓝比 (RBR) 等手工特征，或使用 CNN 提取深度特征。
    4.  **窗口级排除与模态掩码**：如果窗口内图像无效，不丢弃样本，而是生成掩码让模型只依赖结构化数据。
    5.  **系统性滞后修正**：通过最大化相似度扫描全局系统级的时间偏移量。
    6.  **诊断日志**：记录所有清洗动作以确保可重复性。
### 4. 基于智能体的数据处理工作流
文本强调，上述策略不应是静态的检查清单，而应被实例化为一个**推理智能体**的“技能库”。智能体通过分阶段决策来编排这些工具：
1.  **可预测性分析**：先评估目标序列的信号强度。如果信号极弱（如全是夜间数据或严重损坏），直接路由到简单基线模型，**拒绝启动昂贵的多模态融合**，以节省算力。
2.  **数据质量诊断与修复**：根据前述分类学诊断问题，调用对应的修复原语，并记录触发条件和操作日志。
3.  **去噪与降维**：剔除常数通道、高缺失率变量和高度冗余的特征。
4.  **时空对齐**：（文本在此截断）意指根据前述的系统性滞后修正等方法，执行最终的跨模态对齐操作。
**核心理念**：最准确的流水线不一定是把所有预处理步骤都走一遍的流水线。智能体的作用是根据数据的具体“病情”，动态、有针对性地开具“处方”并执行，同时保证整个过程的可审计性。
在你的大一统 Pipeline 架构中，针对这四个原始数据集（GEFCom2014、Folsom、SKIPPD、SunLake），可以通过算法和物理公式从无到有、动态生成以下四大核心板块。
这些特征在原来的独立数据集中要么完全缺失，要么零散不全。通过 Pipeline 生成它们，正是你提炼出“全域特征体系”并投稿 ESSD 的核心价值所在：
1. 确定性天体物理基准（物理天花板特征）
原数据集仅包含零散的实测值，完全缺失理论物理边界。Pipeline 通过各站点的经纬度和 UTC 时间戳，利用 pvlib 统一生成：
dni_clearsky（理论晴空直接法向辐照度）：原数据集均无此物理理论值。
dhi_clearsky（理论晴空散射水平辐照度）：从无到有生成的物理基准。
ghi_clearsky（理论晴空全球水平辐照度）：统一生成的对比基准。
cos_zenith（太阳天顶角余弦值）：用于昼夜判定和夜间硬清零的绝对物理依据。
clearness_index（晴空指数 $k_t$）：通过公式 $\text{GHI}_{\text{actual}} / \text{GHI}_{\text{clearsky}}$ 动态算出的衍生黄金特征（反映云层对太阳光的实际衰减程度）。
2. 匿名站点的绝对地理坐标（地理逆向恢复）
针对数据集：GEFCom2014。
原数据集状态：为了隐私或竞赛公平，原始数据彻底隐藏了辐射站和风电场的经纬度，导致其无法与任何气象、卫星数据联动。
Pipeline 生成部分：利用历史实测功率/辐射与太阳高度角的时序相关性，运行“逆向拟合算法”，强行推导并补全出其真实的经纬度和海拔高度，将其从匿名数据集转化为可空间对齐的地理数据集。
3. 天空全景图的第 4 通道：BRR 薄云增强通道（视觉物理特征）
针对数据集：Folsom、SKIPPD。
原数据集状态：原始数据只有传统的红、绿、蓝（RGB）三通道天空相机图片。
Pipeline 生成部分：在管道流中，主动利用公式 $(\text{B}-\text{R})/(\text{B}+\text{R})$ 逐像素动态计算，在原始 RGB 基础上强行拼接出一个全新的第 4 通道（Blue-to-Red Ratio, 红蓝比通道）。该通道专门用来显式放大“薄云”与“清空蓝天”的边缘反差，提升计算机视觉模型对隐形薄云的捕捉能力。
4. 预测演化帧与空间置信度矩阵（光流外推多模态特征）
针对数据集：Folsom、SKIPPD、SunLake（凡是能对齐广域卫星云图的数据集）。
原数据集状态：卫星云图只有历史和当前时刻的静态快照（Observation），没有未来预演。
Pipeline 生成部分：
未来 K 步外推卫星云图：基于当前连续两帧卫星图，运行 TV-L1 光流算法，直接外推生成未来多个时间步的云层位置演化图。
Uncertainty_Map（不确定性权重矩阵）：利用光流场散度的局地累积积分，随外推步数（Lead Time）和局地变形度动态生成一个 $0.0 \sim 1.0$ 的置信度衰减矩阵（表7第4通道），显式告知下游深度学习模型每一个外推像素的“物理靠谱程度”。
根据你定义的“物理独立存储 + 逻辑大一统”架构以及前述的统一处理 Pipeline 机制，这四个原始数据集（Folsom、SKIPPD、SunLake、GEFCom2014）在通过“算子装配线”处理后，没有任何一个数据集能同时拥有完整的表1到表7。

一、 核心设计理念：物理独立，逻辑统一
为了彻底解决光伏与气象预测领域长期存在的数据集格式异构、多模态时空非同步、缺乏统一物理约束等痛点，本方案放弃了“强行拼表”的传统做法，采用分布式标准库架构 (Distributed Standardized Repository)：
物理存储上：GEFCom2014、Folsom、SKIPPD、SunLake 四个数据集在 Hugging Face 存储库中保持相互独立的子文件夹存放，完美规避了版权冲突与长尾数据空缺（NaN 泛滥）的问题。
逻辑契约上：通过同一套抽象基类 Pipeline（通用算子装配线）进行清洗和特征升维，吐出文件结构、变量命名、张量维度完全镜像对齐的标准包，并由一个全局索引中心统一调度。
二、 统一数据契约结构 (Data Contracts)
每个独立的数据集文件夹下，均统一规范为以下结构：
metadata.parquet (静态元数据注册表)：包含实体 ID、地理坐标（含逆向恢复坐标）、海拔、时区、地表反照率等站点固定物理属性。
time_series.parquet (时序标量综合表)：将原数据集零散的一维变量彻底对齐，并容纳由 Pipeline 统一生成的新特征：
timestamp_utc：全局统一的 UTC 时间轴主键。
cos_zenith / solar_azimuth：太阳天顶角余弦与方位角。
ghi_clearsky / dni_clearsky / dhi_clearsky：【新增】理论晴空三路辐射基准。
clearness_index ($k_t$)：【新增】反映云层衰减的黄金特征（$\text{GHI}_{\text{actual}} / \text{GHI}_{\text{clearsky}}$）。
pv_power_normalized：最大值归一化后的光伏实际发电功率（0~1）。
quality_flag：【新增】自动化质量标签（0:优质, 1:限电限幅, 2:设备异常, 3:夜间清零）。
sky_images.zarr (地面全景图像库)：统一重采样为 $256 \times 256$。包含传统的 RGB 通道，以及 Pipeline 动态追加的第 4 通道 BRR（红蓝比通道，$(\text{B}-\text{R})/(\text{B}+\text{R})$），用于显式放大薄云边界。
satellite_future.zarr (光流外推未来图库)：统一裁剪为以站点为中心 $50\text{km} \times 50\text{km}$ 的标准化网格。包含可见光/红外/水汽通道，以及 Pipeline 动态追加的第 4 通道 Uncertainty_Map（不确定性权重矩阵），根据局地光流场散度和外推步数指数级衰减，为下游大模型提供物理信任度降权依据。

一、 扩展后的多模态抽象基类实现
你可以直接用这段完整代码替换或升级你现有的实现。它在标量流程的基础上，无缝插入了高维张量的动态生成与懒加载导出：
Python
from abc import ABC, abstractmethodimport osimport pandas as pdimport numpy as npimport pvlibimport zarrimport cv2  # 用于高效处理光流和图像重采样
# =====================================================================# 1. 统一处理流水线：多模态大一统抽象基类 (Base Multimodal Pipeline)# =====================================================================class BaseSolarPipeline(ABC):
    def __init__(self, raw_data_dir: str, output_dir: str, dataset_name: str):
        self.raw_data_dir = raw_data_dir
        self.output_dir = os.path.join(output_dir, dataset_name)
        self.dataset_name = dataset_name
        os.makedirs(self.output_dir, exist_ok=True)
    @abstractmethod
    def load_and_standardize_raw(self) -> tuple[pd.DataFrame, pd.DataFrame]:
        """
        [子类必须实现] 返回标准格式的 (元数据表, 原始时序表)
        """
        pass
    @abstractmethod
    def process_and_save_tensors(self, df_ts: pd.DataFrame):
        """
        [子类必须实现] 处理高维张量（天空图或卫星图）。
        由于有些数据集（如GEFCom）没有图像，子类如无图像直接写 pass 即可。
        """
        pass
    # ──── 统一物理算子 ────
    def _compute_clearsky_and_astronomy(self, df_meta: pd.DataFrame, df_ts: pd.DataFrame) -> pd.DataFrame:
        anchors_list = []
        for _, row in df_meta.iterrows():
            entity_id = row['entity_id']
            station_ts = df_ts[df_ts['entity_id'] == entity_id]
            if station_ts.empty: continue
                
            time_index = station_ts.index
            solpos = pvlib.solarposition.get_solarposition(time_index, row['latitude'], row['longitude'], row['elevation_meters'])
            cos_zenith = np.maximum(0.0, np.cos(np.radians(solpos['zenith'].values)))
            ineichen = pvlib.clearsky.ineichen(solpos['apparent_zenith'], appointment_time=time_index)
            
            df_anchor = pd.DataFrame({
                'entity_id': entity_id,
                'cos_zenith': cos_zenith.astype(np.float32),
                'ghi_clearsky': ineichen['ghi'].values.astype(np.float32),
                'dni_clearsky': ineichen['dni'].values.astype(np.float32),
                'dhi_clearsky': ineichen['dhi'].values.astype(np.float32)
            }, index=time_index)
            anchors_list.append(df_anchor)
        return pd.concat(anchors_list)
    # ──── 统一质量审计与特征工程 ────
    def _apply_quality_audit_and_features(self, df_ts: pd.DataFrame, df_anchor: pd.DataFrame) -> pd.DataFrame:
        merged = pd.merge(df_ts, df_anchor, on=['timestamp_utc', 'entity_id'], how='left')
        merged['quality_flag'] = 0 
        
        night_mask = merged['cos_zenith'] <= 0
        merged.loc[night_mask, ['ghi_actual', 'pv_power_normalized']] = 0.0
        merged.loc[night_mask, 'quality_flag'] = 3 
        
        eps = 1e-6
        merged['clearness_index'] = merged['ghi_actual'] / (merged['ghi_clearsky'] + eps)
        merged['clearness_index'] = np.clip(merged['clearness_index'], 0.0, 1.5).astype(np.float32)
        return merged
    # ──── 统一视觉增强算子 (天空相机 BRR 生成) ────
    def _generate_brr_channel(self, rgb_img: np.ndarray) -> np.ndarray:
        """
        输入: (H, W, 3) 的 RGB 图像，值域 0~255
        输出: (4, H, W) 拼接了 BRR 通道的对齐标准化张量
        """
        img_float = rgb_img.astype(np.float32) / 255.0
        r, g, b = img_float[:,:,0], img_float[:,:,1], img_float[:,:,2]
        
        # 计算红蓝比通道 (B-R)/(B+R)
        eps = 1e-6
        brr = (b - r) / (b + r + eps)
        brr = np.clip(brr, -1.0, 1.0)
        
        # 重新堆叠为通道优先格式 (4, H, W)
        multimodal_tensor = np.stack([r, g, b, brr], axis=0)
        return multimodal_tensor
    # ──── 统一动力学算子 (卫星云图光流外推 + 不确定性矩阵) ────
    def _extrapolate_satellite_flow(self, img_t0: np.ndarray, img_t1: np.ndarray, steps_k: int) -> tuple[np.ndarray, np.ndarray]:
        """
        基于连续两帧卫星图计算 TV-L1 光流，并向未来外推 K 步，同时输出置信度权重图
        """
        # 转换为灰度图计算光流
        gray0 = cv2.cvtColor((img_t0 * 255).astype(np.uint8), cv2.COLOR_RGB2GRAY)
        gray1 = cv2.cvtColor((img_t1 * 255).astype(np.uint8), cv2.COLOR_RGB2GRAY)
        
        # 构建 TV-L1 光流器并计算速度场 (u, v)
        tvl1 = cv2.optflow.createOptFlow_DualTVL1()
        flow = tvl1.calc(gray0, gray1, None)
        u, v = flow[..., 0], flow[..., 1]
        
        # 计算速度场散度 Divergence (用于不确定性度量)
        du_dx = cv2.Sobel(u, cv2.CV_32F, 1, 0, ksize=3)
        dv_dy = cv2.Sobel(v, cv2.CV_32F, 0, 1, ksize=3)
        divergence = np.abs(du_dx + dv_dy)
        
        h, w, c = img_t1.shape
        future_frames = []
        uncertainty_maps = []
        
        # 沿半拉格朗日平移外推 K 步
        for k in range(1, steps_k + 1):
            map_x, map_y = np.meshgrid(np.arange(w), np.arange(h))
            map_x = (map_x + k * u).astype(np.float32)
            map_y = (map_y + k * v).astype(np.float32)
            
            # 图像像素外推重映射
            warped_frame = cv2.remap(img_t1, map_x, map_y, cv2.INTER_LINEAR, borderMode=cv2.BORDER_REPLICATE)
            future_frames.append(warped_frame)
            
            # 动态计算不确定性矩阵（随步数指数衰减，随散度增大而置信度暴跌）
            alpha, beta = 0.02, 0.05
            u_map = np.exp(-alpha * k) * (1.0 - np.minimum(1.0, beta * k * divergence))
            uncertainty_maps.append(np.clip(u_map, 0.0, 1.0))
            
        return np.array(future_frames), np.array(uncertainty_maps)
    # ──── 统一骨架主控流 ────
    def run_pipeline(self):
        print(f"================== 开始处理多模态数据集: {self.dataset_name} ==================")
        
        # 1. 标量流解析与生成
        df_meta, df_ts = self.load_and_standardize_raw()
        print("-> 正在运行物理晴空算子...")
        df_anchor = self._compute_clearsky_and_astronomy(df_meta, df_ts)
        print("-> 正在自动化质量审计与特征升级...")
        df_final_ts = self._apply_quality_audit_and_features(df_ts, df_anchor)
        
        # 2. 独立存储标量表
        df_meta.to_parquet(os.path.join(self.output_dir, "metadata.parquet"))
        df_final_ts.to_parquet(os.path.join(self.output_dir, "time_series.parquet"))
        
        # 3. 动态触发高维多模态图像算子
        print("-> 正在执行子类多模态图像/张量生命周期处理...")
        self.process_and_save_tensors(df_final_ts)
        
        print(f"================== {self.dataset_name} 独立大一统标准包构建完成！ ==================\n")
二、 子类多模态适配器实现示例
在扩展后的流水线架构下，子类适配器除了对齐表格，还负责将图像重抽样并通过通用基类算子清洗注入 Zarr。以下以包含天空相机的 FolsomPipeline 为例：
Python
class FolsomPipeline(BaseSolarPipeline):
    def load_and_standardize_raw(self) -> tuple[pd.DataFrame, pd.DataFrame]:
        # 保持你原有的表格对齐逻辑不变
        df_meta = pd.DataFrame([{
            'entity_id': 'FOLSOM_STN_A',
            'dataset_source': 'Folsom',
            'latitude': 38.69, 'longitude': -121.18, 'elevation_meters': 100.0,
            'local_timezone': 'America/Los_Angeles'
        }])
        
        # 模拟读取原始时序
        idx = pd.date_range(start="2026-06-01 08:00", periods=5, freq="1-min", tz="UTC")
        df_ts = pd.DataFrame({
            'entity_id': 'FOLSOM_STN_A',
            'ghi_actual': [100.0, 250.0, 400.0, 600.0, 800.0],
            'pv_power_normalized': [np.nan]*5
        }, index=idx)
        df_ts.index.name = 'timestamp_utc'
        return df_meta, df_ts
    def process_and_save_tensors(self, df_ts: pd.DataFrame):
        """
        实现 Folsom 专属的视觉图像自动对齐与 Zarr 存储
        """
        zarr_path = os.path.join(self.output_dir, "sky_images.zarr")
        
        # 初始化固定分辨率的 Zarr 巨型图像立方体 (N_时间步, 4通道, 256_高, 256_宽)
        num_steps = len(df_ts)
        store = zarr.DirectoryStore(zarr_path)
        root = zarr.group(store=store, overwrite=True)
        
        # 分块（Chunking）是即插即用懒加载的核心，按 (1, 4, 256, 256) 切块利于秒级云端检索
        z_img = root.empty('images', shape=(num_steps, 4, 256, 256), 
                           chunks=(1, 4, 256, 256), dtype='float32')
        
        print(f"   [视觉适配] 正在为 {num_steps} 个时序节点匹配并追加 BRR 增强特征层...")
        for i, timestamp in enumerate(df_ts.index):
            # 1. 模拟读取原始异构图片 (实际中根据真实路径读取)
            # mock_raw_img = cv2.imread(f"{self.raw_data_dir}/{timestamp.strftime('%Y%m%d%H%M')}.jpg")
            mock_raw_img = np.random.randint(0, 255, (512, 512, 3), dtype=np.uint8) # 模拟原图 512x512
            
            # 2. 强制空间重采样对齐到统一格式 256x256
            resized_img = cv2.resize(mock_raw_img, (256, 256), interpolation=cv2.INTER_AREA)
            
            # 3. 调用基类统一算子生成全新的 4 通道多模态张量（含BRR）
            four_channel_tensor = self._generate_brr_channel(resized_img)
            
            # 4. 写入懒加载 Zarr 阵列
            z_img[i] = four_channel_tensor
            
        print(f"   [视觉适配] Zarr 库已成功建立并完成分块压缩导出。")
三、 全局调用
运行逻辑完全不需要改变。不论数据集包含纯标量还是复杂的卫星图片，只要执行 pipeline.run_pipeline()，这套大一统的“算子装配线”都会根据子类内部声明的模态自动清洗、补全，并规范化存储到你指定的物理路径中。
1. 官方标准命名（最推荐，辨识度最高）
项目名称：SolarUniBench 或者 solar-unibench
推荐理由：与数据集名字完全一致。GitHub 上的主页直接对应论文标题，别人在论文里看到 SolarUniBench 就能在 GitHub 上秒搜到你。
Repository 简介 (About) 写法：
📦 Official implementation of "SolarUniBench-v1.0": A Multi-modal Standardized Dataset and Distributed Processing Pipeline for Harmonized Solar Forecasting.
💡 最佳开源架构落地建议
在 GitHub 创建项目后，你的项目根目录可以设计得非常专业：
Markdown
